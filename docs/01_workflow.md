
# 01_workflow — 委任ルール / 実行フロー

このドキュメントは「どの agent に何をやらせるか」を決めるための運用ルールです。
役割分担は固定（Opus 司令塔 / Codex 主実装 / Claude UI専門）。迷ったらこの決定木に戻ります。

## 基本原則

- **分解が最重要**: 依頼文が曖昧だと、成果物も曖昧になる
- **最小差分**: 無関係な変更は混ぜない（特に既存 repo）
- **再現性**: 何を確認したか、何が未確認かを明確に残す
- **安全優先**: `/tmp` 禁止、`git add -A` 禁止、`--no-verify` 禁止、秘密は書かない

## 委任の決定木 (タスク特性 → 宛先)

```
START
  |
  |-- UI / 画面操作 / ブラウザ / 画像確認が中心？
  |       -> YES: Claude Code (Sonnet) を第一候補
  |       ->  NO
  |
  |-- 実装 + テスト + git 操作まで一気通貫が必要？
  |       -> YES: Codex (GPT-5.5) を第一候補
  |       ->  NO
  |
  |-- 調査・設計・比較検討が中心？（書かない方が良い）
  |       -> YES: Opus (司令塔) が要約し、必要箇所だけ委任
  |       ->  NO
  |
  |-- 既存 repo の大規模変更で競合が怖い？
  |       -> YES: まず Opus が分割し、Codex に小さく投げる
  |       ->  NO: Codex に投げて OK
```

## 依頼文の 6 ブロック構造 (delegate_prompt)

依頼文はこの 6 ブロックに固定します。短くても良いが、欠けると事故が増えます。

1. **経緯 / 背景**: なぜ今やるか、何が決定事項か
2. **作業 dir / リポジトリ**: 絶対パス、ブランチ、対象 repo
3. **現状**: git status / 既存構造 / 既知の制約
4. **DoD (Definition of Done)**: 受け入れ条件、成果物、検証
5. **禁止事項 (MUST NOT)**: やってはいけないこと（例: git add -A, /tmp, secrets）
6. **完了報告フォーマット**: 何を貼って終わるか（log/diff/検証/残課題）

テンプレは `templates/delegate_prompt.md.tmpl`。

## DoD の作り方 (チェックリスト)

- 成果物は「ファイル名 / コマンド / 画面」まで指定できているか
- 変更範囲が明確か（触って良いディレクトリ / 触るな）
- 検証が含まれているか（build/test/health check）
- 「完了」判定が客観か（主観語だけで終わらない）

## Codex に投げるときのコツ

- **小さく投げる**: 1 回の依頼は 1〜3 目的に絞る（大きいと事故る）
- **差分駆動**: 変更したいファイルを先に列挙し、ゴールから逆算する
- **Git 制約を最初に書く**: `git add -A` 禁止、`--no-verify` 禁止、`main` force 禁止
- **テストがあるなら最小のテストコマンドを明示**する

## Claude Code に投げるときのコツ (UI/computer-use)

- 画面で「何を見れば完了か」を明確にする（スクショ / URL / UI 名）
- 操作手順は番号付きで。迷ったら「やらない」判断を含める
- UI 変更は必ず **before/after を文章で要約**する（差分が見えづらい）

## openclaw を挟むとき

openclaw は「handoff の束ね」「context-file の生成」「委任のパイプライン化」に使う。

使いどころ:

- 次セッションへ引き継ぐ（handoff-pack）
- 複数 agent への委任を同じ形式に揃える
- 長い作業の checkpoint を作る

## 進め方の型 (最小の運用)

1. `PROJECT_STATUS.md` を更新（今から触る範囲 / 目的 / 残課題）
2. 6 ブロック依頼文で実装を委任
3. 実装者は「変更 / 検証 / 残課題」を同じ形式で報告
4. handoff-pack で状態を束ねる（途中でも OK）

## ありがちな失敗と回避

- **タスクがでかすぎる** → Opus が分割してから投げる
- **禁止事項が抜ける** → 依頼文テンプレを必ず使う
- **/tmp を使う** → 作業 dir を最初に絶対パスで固定する
- **git add -A** → 依頼文に「明示パス add」を強制する
- **検証がない** → DoD に “実行したコマンド” を含める

次は `docs/02_context_engineering.md` で「context の設計」を読む。
