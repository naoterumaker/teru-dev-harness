
# 05_lessons — 事故事例と再発防止

このドキュメントは「やらかしの記録」です。
恥ではなく資産。事故は “発生した時点で” ルールに落として再発確率を下げる。

## 目的

- 失敗のパターンを言語化し、次回は機械的に回避する
- ルール（`AGENTS.md`）とテンプレ（`templates/`）へフィードバックする
- “なぜその禁則があるのか” を将来の自分に説明できるようにする

## 事故 1: 2026-05-04 — gamification 沼 → 194 commits revert

### 何が起きたか

- “楽しくするための仕掛け” を思いつきで入れ始めた
- 本筋と無関係な変更が増殖し、レビュー不能に
- 最終的に 194 commits をまとめて revert する事態に

### 根本原因

- DoD とロードマップが曖昧なまま “思いつき” を許した
- 1 commit = 1 領域が守られず、変更が混ざった
- 「いま必要な価値」より「やりたくなる作業」を優先してしまった

### 再発防止 (ルール化)

- 仕様書ロードマップ外の feature を勝手に追加しない（`AGENTS.md` に明記）
- “面白そう” は issue/todo に隔離し、当日の実装に混ぜない
- 依頼文（6 ブロック）に “MUST NOT: roadmap 外 feature” を書く

### 早期検知のサイン

- PR/差分の説明が “なんとなく” になる
- 変更ファイルが目的と一致しない
- 「戻せる」前提で実験が常態化する

## 事故 2: 2026-05-05 — Operator mode を削除 (-2149 lines)

### 何が起きたか

- “危険そうだから消す” という判断で Operator mode を一括削除
- 依存関係（参照箇所、利用者、テスト）を十分に追っていなかった
- 影響範囲が大きく、結果的に手戻りを生んだ

### 根本原因

- “削除” は破壊的変更なのに、DoD が「安全に消せた」になっていなかった
- 変更前の SoT（仕様/利用箇所/目的）が揃っていなかった
- 「段階的無効化→観測→削除」の順序を踏まなかった

### 再発防止 (ルール化)

- 大規模削除は段階を踏む（disable → measure → delete）
- “削除系タスク” は DoD に必ず以下を含める:
  - 参照箇所の列挙
  - 代替手段の確認
  - テスト/起動確認
  - ロールバック手順

## 事故 3: 2026-05-07 — /private/tmp 大量喪失

### 何が起きたか

- 作業ディレクトリを `/private/tmp` 配下に置いていた
- macOS の cleanup でディレクトリが消え、成果物・中間ファイルが喪失
- 復旧のために余計な時間が発生

### 根本原因

- OS の仕様（短命ディレクトリ）を軽視していた
- “作業 dir を絶対パスで固定する” ルールがなく、場当たりだった

### 再発防止 (ルール化)

- `/tmp` と `/private/tmp` 配下での作業を全面禁止（`AGENTS.md` に明記）
- 依頼文に “Workdir (absolute)” を必須項目として入れる
- 重要な生成物は repo 内に置く（もしくは永続ディレクトリ）

## 事故 4: 2026-05-08 — cron env var 漏れ → daemon が空動作

### 何が起きたか

- cron から起動する daemon が環境変数を読めず、API key 等が未設定
- “起動したが実質何もしない” 状態で空運用が続いた

### 根本原因

- cron は対話シェルと環境が違う（PATH/ENV が引き継がれない）
- “health check” が不足し、失敗に気づけなかった
- “起動するだけ” で OK と誤認していた

### 再発防止 (ルール化)

- `bootstrap/verify.sh` のような health check を常設し、起動後に必ず実行する
- `.env` は “存在チェック” と “必須キーの空チェック” を入れる
- “動作している証跡” をログに出す（何を処理したか、0 件なら 0 件と出す）

## 事故から抽出した共通ルール

- **破壊的変更は段階的に**（無効化→観測→削除）
- **作業 dir は永続領域**（/tmp 禁止、絶対パス）
- **自動化には健康診断**（verify/doctor、必須 env の検査）
- **面白そうは隔離**（ロードマップ外は TODO へ）

## 更新ルール

- 事故が起きたら当日中に追記する（短くて良い）
- 追記したら必ずどこかを更新する:
  - `AGENTS.md` の禁則
  - `templates/` の項目
  - `bootstrap/verify.sh` の検査項目
